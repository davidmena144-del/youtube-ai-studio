# YouTube AI Studio — الخطة المعمارية وخطة التنفيذ

> آخر تحديث: 2026-11-15 — الحالة: **المرحلة 1 مكتملة وتنتظر اختبارك** (انظر [حالة المراحل](#حالة-المراحل)).

## 1. نتيجة فحص المستودع

المستودع كان فارغًا تقريبًا: commit واحد (`Initial commit`) يحتوي `README.md` بعنوان فقط. لا يوجد كود سابق، ولا إعدادات، ولا أسرار، ولا تكاملات قائمة. لذلك صُمم المشروع من الصفر.

## 2. المبادئ الحاكمة

1. **سحابي بالكامل**: لا شيء يتطلب كمبيوتر محليًا أو Termux. التطوير يتم عبر Claude Code (جلسات سحابية) و GitHub، والتشغيل على خدمات استضافة.
2. **يعمل بدون أي مفاتيح**: كل مزوّد (LLM، صوت، فيديو، نشر) له وضع `mock` أو `dry_run` مجاني يعمل فورًا، ويُفعَّل المزوّد الحقيقي فقط عند وجود مفتاحه.
3. **مزوّدون قابلون للاستبدال**: كل خدمة خارجية خلف واجهة (interface) في `src/server/providers/*`. استبدال ElevenLabs بـ Piper مثلًا = إضافة ملف واحد دون لمس بقية النظام.
4. **لا نشر حقيقي قبل اختبارك**: وضع النشر الافتراضي `dry_run`، والنشر الحقيقي غير مبني أصلًا في المرحلة 1، وسيتطلب لاحقًا تفعيلًا صريحًا منك + موافقة على كل فيديو.
5. **لا تكاليف تلقائية**: لا يُنشأ أي حساب أو اشتراك أو مورد مدفوع دون موافقتك. كل الخيارات الافتراضية ضمن الطبقات المجانية.
6. **الصدق في الحالة**: لوحة الإعدادات تعرض لكل مزوّد: `غير مُعدّ` / `مُعدّ — لم يُختبر` / `مُختبر`، ولا نصف تكاملًا بأنه يعمل قبل اختباره فعليًا.

### 3.1 Claude Manager

منسّق مكتوب بالكود (workflow محدد المراحل) وليس وكيلًا حرًّا — هذا أكثر موثوقية وأرخص وقابل للتتبع:

- يعرّف **خط الإنتاج** لكل نوع (`long` / `short`): `research → script → direction → seo → qa → مراجعة بشرية → نشر`.
- يشغّل كل مرحلة كمهمة (job) مستقلة في الطابور، فيحفظ مخرجاتها كـ **artifact بإصدار** (version) ويسجل كل شيء في History.
- يقرأ تقرير QA: إن فشل، يعيد كتابة السيناريو تلقائيًا مع ملاحظات المراجِع (حد أقصى قابل للضبط، افتراضيًا مرة واحدة)، ثم يعيد المراحل اللاحقة.
- يطبّق **بوابة الموافقة**: لا يمكن النشر إلا لمشروع حالته `approved`، ورفضك مع ملاحظات يعيد التشغيل من المرحلة التي تختارها.
- كل وكيل له: مخطط مخرجات صارم (Zod) + تعليمات نظام + مخرجات mock حتمية للاختبار.

### 3.2 الطابور، الأخطاء، إعادة المحاولة، منع التكرار

- طابور داخل PostgreSQL (لا حاجة لـ Redis): `FOR UPDATE SKIP LOCKED` لسحب آمن مع عدة workers.
- إعادة محاولة بتأخير أُسّي + عشوائية (exponential backoff + jitter)، وحد أقصى للمحاولات، ثم حالة `dead` مع ظهور الخطأ في اللوحة وزر "إعادة المحاولة".
- تصنيف الأخطاء: أخطاء مؤقتة (429، 5xx، شبكة) تُعاد، وأخطاء دائمة (مفتاح خاطئ، إعداد ناقص) تتوقف فورًا.
- استرجاع المهام العالقة (worker توقف فجأة) عبر lease timeout.
- **منع تكرار النشر** على ثلاث طبقات: `idempotency_key` فريد لكل مهمة، فهرس فريد جزئي يمنع وجود أكثر من نشر غير فاشل لنفس المشروع، وفحص حالة قبل الرفع. (في المرحلة 3 نضيف: حفظ `videoId` فور استلامه، والتحقق من القناة قبل إعادة أي رفع فاشل.)

### 3.3 الأمان وحماية الأسرار

- مفاتيح API تعيش **فقط** في متغيرات البيئة لدى مزود الاستضافة (Vercel / GitHub Secrets) — لا في الكود، ولا في قاعدة البيانات كنص، ولا تُرسل للمتصفح أبدًا.
- الأسرار التي يجب حفظها في القاعدة (مثل refresh token الخاص بـ YouTube في المرحلة 3) تُشفَّر بـ **AES-256-GCM** بمفتاح `ENCRYPTION_KEY` منفصل.
- كلمة مرور المسؤول تُخزن كـ hash (scrypt)، وجلسة موقعة HMAC بكوكي `HttpOnly + Secure + SameSite=Lax`، وحد لمحاولات الدخول الفاشلة.
- Server Actions تتحقق من الجلسة داخليًا (لا نعتمد على حماية الواجهة)، و Next.js يتحقق من Origin تلقائيًا ضد CSRF.
- ترويسات أمان (X-Frame-Options، nosniff، Referrer-Policy، Permissions-Policy).
- نقطة `/api/worker/tick` محمية بـ `CRON_SECRET` (مقارنة ثابتة الزمن).
- سجل History لا يحفظ أي قيمة سرية.

## 5. التكلفة المتوقعة

> الأسعار تقريبية بتاريخ كتابة الخطة ويجب التحقق منها عند التسجيل. **لن أنشئ أي حساب أو أفعّل أي خدمة مدفوعة دون موافقتك.**

### 5.1 المسار المجاني بالكامل (الافتراضي)

| الخدمة | الاستخدام | الطبقة المجانية | التكلفة |
|---|---|---|---|
| Vercel Hobby | الواجهة + API | مجاني للاستخدام الشخصي غير التجاري | $0 |
| Neon أو Supabase | PostgreSQL | ~0.5 GB (Neon) / 500 MB (Supabase، يتوقف المشروع بعد أسبوع خمول) | $0 |
| GitHub Actions | الـ worker + CI | 2,000 دقيقة/شهر للمستودع الخاص (غير محدود للعام) | $0 |
| Cloudflare R2 (م2) | ملفات الفيديو | 10 GB تخزين، بلا رسوم نقل | $0 |
| YouTube Data API (م3) | الرفع والجدولة | 10,000 وحدة/يوم (الرفع يكلف وحدات كثيرة — يكفي لعدة فيديوهات يوميًا) | $0 |
| Piper TTS / ffmpeg / Pexels | صوت / مونتاج / لقطات | مفتوح المصدر / مفتاح مجاني | $0 |
| LLM في وضع mock | محتوى قالبي للاختبار فقط | — | $0 |

**بهذا المسار يعمل النظام بالكامل، لكن المحتوى النصي سيكون قالبيًا (mock) وليس ذكاءً حقيقيًا.**

## 6. المراحل

### المرحلة 1 — الأساس وخط إنتاج المحتوى النصي ✅ (الحالية)
- هيكل المشروع، قاعدة البيانات والـ migrations، الطابور مع إعادة المحاولة ومنع التكرار.
- Claude Manager + وكلاء: البحث، السيناريو، الإخراج (storyboard)، SEO، مراجعة الجودة.
- مزوّد LLM: `mock` (مجاني) و `anthropic` (يُفعّل بالمفتاح).
- دعم الفيديو الطويل و Shorts بإعدادات مختلفة (المدة، البنية، قواعد QA).
- الواجهة (عربي، RTL، موبايل أولًا، PWA): الدخول، لوحة التحكم، المشاريع، إنشاء مشروع بموضوعك، صفحة المشروع (المراحل، المخرجات، المراجعة والموافقة/الرفض)، التقويم، History، المهام، الإعدادات.
- نظام المراجعة والموافقة + "نشر تجريبي" (dry-run) يثبت بوابة الموافقة ومنع التكرار دون أي اتصال بـ YouTube.
- التشفير، الجلسات، حد المحاولات، ترويسات الأمان.
- اختبارات تلقائية + CI + workflow للـ worker على GitHub Actions (معطّل حتى تفعّله).

### المرحلة 2 — الإنتاج الإعلامي
- واجهة Storage (محلي / R2 / Supabase) وصفحة معاينة الملفات.
- TTS: mock (صمت بالطول الصحيح) → Piper (مجاني) → ElevenLabs (اختياري).
- الترجمة: SRT/VTT من السيناريو + توقيت الصوت.
- المرئيات: بطاقات نصية مولدة + Pexels/Pixabay (مفتاح مجاني).
- المونتاج بـ ffmpeg: 16:9 و 9:16، ترجمة مدمجة اختياريًا، موسيقى خلفية مرخصة.
- الصورة المصغرة: قوالب مولدة بالكود + خيار رفع صورتك.
- QA للوسائط (المدة، الأبعاد، مستوى الصوت).

### المرحلة 3 — المراجعة النهائية وتكامل YouTube
- مشغّل معاينة للفيديو والمصغرة قبل الموافقة.
- ربط حساب Google عبر OAuth (Google Cloud project مجاني)، وتخزين refresh token مشفرًا.
- رفع قابل للاستئناف، رفع المصغرة والترجمات، الجدولة بـ `publishAt`.
- تتبع حصة الـ API، ومنع التكرار المتقدم.
- **تنبيه مهم**: مشاريع Google Cloud غير المُدقَّقة تُقفل الفيديوهات المرفوعة عبر الـ API على وضع "خاص" حتى يجتاز المشروع تدقيق Google. سنختبر أولًا برفع خاص، ثم نقرر معك طلب التدقيق.
- النشر الحقيقي يتطلب: `PUBLISHING_MODE=live` + موافقتك على المشروع + تأكيد صريح عند الضغط.

### المرحلة 4 — الأتمتة اليومية والتقويم
- قائمة مواضيع تحددها أنت + جدول يومي ينتج تلقائيًا ويضع النتائج في انتظار مراجعتك.
- تقويم تفاعلي (سحب وإفلات للمواعيد)، إشعارات (بريد/Push).
- سحب إحصاءات الأداء (YouTube Analytics) لكل فيديو.

### المرحلة 5 — التقوية والتوسع
- مراقبة وتنبيهات، نسخ احتياطي، حدود إنفاق لكل مزوّد، تعدد القنوات، دخول عبر Google.
